## Coordinates and directions

Local points are `[x,y,z]`: positive x is anatomical left, positive y is down, positive z is forward. Front-view screen-left is therefore anatomical right. `chibi8SVG(character, yawIndex)` uses `yawIndex * 45` degrees, with signed and fractional values supported. Principal indices 0–7 are front, front facing screen-right, right profile, rear-right, back, rear-left, left profile, rear facing screen-left.

`project()` rotates x/z and returns screen x, screen y and depth. Bézier controls are projected with their endpoints. The front-facing factor is a surface visibility cue, while depth controls layer order. These serve different purposes. Keep an asymmetric feature in local coordinates; do not duplicate a finished view with a negative screen scale.

## Focused overrides

Load the source as a classic script. Use the existing record as the starting point and explicitly merge the nested record you are changing:

```js
const study = {
  ...STUDY_CHARS.mariaBrown,
  geometry: {
    ...BROWN_MARIA_GEOMETRY,
    scarf: { ...BROWN_MARIA_GEOMETRY.scarf, sag: 7 }
  }
};
const quarterView = chibi8SVG(study, 1);
const intermediateView = chibi8SVG(study, 1.5);
```

`c.geometry` replaces the selected geometry record; it is not a recursive partial override. Do not supply only the changed key. Keep material colours distinct from the game's lighting. Soft/layered paint remains an internal comparison option.
