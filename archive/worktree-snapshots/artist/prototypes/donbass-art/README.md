## API for another Codex chat

Load src/chibi8.js as a classic script. `chibi8SVG(STUDY_CHARS.mariaBrown, yawIndex)` returns an SVG with its character bounds (brown currently: `0 -27 200 271` for the large tuft; read the returned viewBox when changing head height; teal and legacy: `0 0 200 244`). yawIndex 0=front, 1=front toward screen-right, 2=right profile, 4=back, 6=left; fractional indices preserve intermediate angles. No scaleX(-1) is needed. Angles in the preview are degrees divided by 45. For the existing greybox sector convention, use `(4 - sector + 8) % 8`.

Parameters live in STUDY_CHARS: palette, outline, tuftAz, faceArc, eyeAz, expression, pose, belt, buckleAz and costume. MARIA_GEOMETRY near the top of the same file contains fringe, templeLocks, faceRows and crownCap. Supply a geometry record on c.geometry to override them. Each curve contains a start point and cubic segments of [control1, control2, endpoint], with local coordinates [anatomical-left x, down y, forward z]. faceRows are [y, cross-section radius, forward chin offset]; crownCap is a 2D cover joining the roots. The torso, bob envelope, jaw envelope and shoe construction remain in the renderer. The bob and shoes use solid yaw-dependent silhouette envelopes so flat planes do not collapse edge-on. The outline is the primary stroke width; detail strokes are currently explicit in the construction code. Negative azimuth is the character's right, positive her left in the front view. Those are character-space positions, not screen-space assignments. Pose may be relaxed, crossed or explain (speaking gesture); forearms are projected and depth ordered. Expression may be neutral, happy, stare, shocked, confused or delusional; cos may be null or wizard (Maria) or knight (baseline). The asymmetric fringe and tuft keep these positions as the figure turns. Screen-R labels indicate facing direction, not anatomical side.

Projection, visibility and draw order remain distinct. Far arms are drawn behind the torso rather than deleted at a threshold; feet are depth sorted; front collar and back seam follow yaw. The clipped fringe is projected from head landmarks. IDs are unique across copies; the working renderer uses a distinct prefix from the baseline. The caller should validate externally supplied character parameters; this API is for trusted local data, not untrusted uploads.

For eventual integration, first get the owner's aesthetic approval, then copy only the working renderer and approved parameters into the current editable game source in a separate task. Cache eight principal SVGs or approved rasterizations for gameplay rather than rebuilding SVG every frame. Do not copy vendor/, research/, references/, preview code, or the older mirrored renderer into the game. Leave the Worker bindings/configuration and live public/ untouched. Keep intermediate angles if the caller uses them.
